# Task 6: Clients API with TypeORM

Task 6 continues Task 5 and uses the same PostgreSQL database and existing
`sellers`, `products`, and `seller_products` tables. Database reads and writes
are handled through TypeORM repositories and query builders.

## Setup

Install dependencies from this folder:

```powershell
npm install
```

Task 5's database connection settings are copied into this folder's `.env`.
For another machine, copy `.env.example` to `.env` and enter the settings for
the database containing your existing tables.

Start the API:

```powershell
npm start
```

The API runs at `http://localhost:3100` by default. TypeORM synchronization is
disabled; startup will not create, alter, or replace database tables.

## Tables

- `sellers`: `id`, `seller_name`, `email`
- `products`: `id`, `seller_id`, `product`, `added_at`
- `seller_products`: `id`, `seller_name`, `email`, `product`, `price`, `added_at`

Product `seller_id` values must refer to an existing seller.

## Routes

The same operations are available for `/sellers`, `/products`, and
`/seller_products`:

| Method | Example | Description |
| --- | --- | --- |
| GET | `/sellers` | List all rows |
| GET | `/sellers?search=ahmed` | Search rows |
| GET | `/sellers/1` | Get one row by ID |
| POST | `/sellers` | Create a row |
| PUT | `/sellers/1` | Replace all editable fields |
| PATCH | `/sellers/1` | Update supplied fields |
| DELETE | `/sellers/1` | Delete a row |

`/seller-products` is also accepted as an alias for `/seller_products`.
Search is case-insensitive; `?q=word` is an alias for `?search=word`.

Seller search returns matching sellers with their products and any matching
price from `seller_products`. Product search returns matching products with
seller details and any matching price.

## Request examples

Create a seller:

```json
POST /sellers
{
  "seller_name": "Ahmed Store",
  "email": "ahmed@example.com"
}
```

Create a product:

```json
POST /products
{
  "seller_id": 1,
  "product": "Wireless mouse"
}
```

Create a seller-product record:

```json
POST /seller_products
{
  "seller_name": "Ahmed Store",
  "email": "ahmed@example.com",
  "product": "Wireless mouse",
  "price": 250.00
}
```

IDs and `added_at` are generated by the database; do not include them in request
bodies. `PUT` requires every editable field, while `PATCH` requires at least one.
Invalid input returns status `400`; missing IDs return `404`.
